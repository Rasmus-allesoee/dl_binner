# Next block: confidence-aware hierarchical taxonomy

Proposed November 6, 2026, after the [completed E034 pilots](completed-review.md).
This is local implementation/preparation scope for a new research branch and
experiment, not authority to reuse E034's unused money, wake compute or acquire
a reference collection. [Source/alternatives assessment](../../docs/evidence/2026-11-06-e034-pilot-and-information-priority.md)
owns the evidence and the change of direction.

## Recovery target and coherent candidate

Improve grouping of fragmented cellular genomes, beyond E032's largely singleton-
associated Oral gain, while retaining strong E009 recovery. Reliable external
annotation could add biological context that ten depth columns and currently
sparse/ambiguous physical links do not provide. This is not a guaranteed gain;
freeze and test one candidate against the strongest accepted evidence.

Start from preserved E031 bootstrap/source/state and full DNA views. Implement
one optional hierarchical-taxonomy branch and learning objective with explicit
composition, measured-depth and optional admitted GLM paths. Resolve the precise
fusion, taxonomy loss, confidence/abstention, initialization, modality dropout and
schedule through the pinned TaxVAMB/Taxometer source and real engineering tests.
Do not automatically copy their entire VAE, annotation propagation, 300-epoch
schedule or greater-than-2-kb eligibility. Existing parent/crop semantics and
bootstrap state transfers need explicit contracts; taxonomy is parent context
unless actually measured on crop DNA. Unknown and partial classifications require
real masks, not fabricated leaves or uniform confident labels.

Retain intrinsic within-taxon distinctions. Same genus/species is not a must-link,
and an uncertain difference is not an unconditional cannot-link. No hard component
union, truth K, forced genome count, marker-family blacklist or taxon-specific
product routing. Marker calls/refinement stay cached and conservative. Preserve
all short/marker-negative, novel/unannotated, unknown/non-target, excluded and
unassigned DNA. Keep E032 construction fixed for the first representation test;
do not simultaneously optimize its selector to the new annotations.

Use one common implementation and classifier/database policy across E009 no-GLM,
E009 GLM and Oral ten-depth/no-GLM. E009 GLM retains actual GLM teacher/proposal
inputs as well as student inputs; no-GLM modes have no hidden GLM priors. Any new
teacher/proposal path must use the declared information policy. Retain E023
10.4163%, stronger E031 E023 contexts, E032 and both native MetaBAT2 references
unchanged. A taxonomy-off companion is the one potentially decision-changing
information control; freeze it only if needed, preserving module construction,
initialization, RNG and nonparameter state. No factorial/grid or old refit/rescore.

## Annotation and database admission

Prepare one pinned independent MMseqs2/GTDB classification path, or justify a
better supported alternative before freezing. Source-check the **actual** released
classifier and database, taxonomy tree/ranks, LCA/support/ambiguity semantics,
query type, source-blind ID mapping and emitted schema. Do not assume MMseqs2's
current `GTDB` download still names the paper's release 220. Pin full payload
member identities and release; record reference-genome overlap/provenance where
available. Use bounded metadata/HEAD/range checks and tiny real synthetic query/
reference contracts during local preparation, without bulk database acquisition
or classification of E009/Oral. Report unavailable native paths honestly.

No simulator genome/accession/taxon/coordinate join, source-origin oracle, native
benchmark taxonomy or evaluator label may enter annotations or model inputs.
Classification must come from actual DNA and an independently frozen reference.
Keep the reverse opaque-ID/source join outside the feature path. Preserve complete
no-hit, conflict and partial-rank records. Score confidence is not automatically
calibrated accuracy. Reference-free and reference-assisted mode claims must stay
distinct, including database overlaps and novelty limitations.

Sparse tree/path encodings and batched losses are required at Oral scale; avoid
a 1.29-million-row dense taxon one-hot table. Preserve input annotations separately
from model-propagated predictions. Do not treat predictions learned from our own
TNF/depth as another independent measurement. Actual classifier yield, RAM, time,
temporary coexistence and complete schedule must admit future community use.

## Checks, comparison and resource case

Implement directly after a concise prospective design. Run real tiny parser/tree/
partial-label/conflict/zero-annotation/gradient/state/Adam/reload/unit-geometry/
cached-marker/refinement/export tests and a complete bounded serial tiny workflow.
Use generated annotation fixtures only where clearly labeled; they are not native
community classifier or database admission. Preserve features, annotations and
confidence, embeddings, alternatives and full exports. Freeze source/defaults,
all availability modes, keep/modify/abandon criteria and the whole return/review
contract before any changed community outcomes. Recovery, not annotation accuracy
alone, decides whether the candidate is useful.

The future comparison must retain full 156/799 reference denominators, conservative
E009 v2/3.3034% N-quarantine, separate Oral provided-origin/known-shared sensitivity,
target-level gains/losses and length/origin/annotation/eligibility/marker/unassigned/
singleton/multi-contig strata. Require substantive fragmented-genome gains without
hiding E009 or unknown-lineage regressions. Practical effects must be prospectively
chosen, not borrowed from another method's published scores or tuned afterward.

about 26.8 GiB. A taxonomy database, index, query ORFs/results and extraction scratch
