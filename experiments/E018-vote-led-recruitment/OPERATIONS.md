## Execution

1. Commit/check/push exact clean prepared source on the descriptive branch;
   retain all old source commits. Refresh signed-in Welcome balance/scope/expiry,
   delayed usage, actual current eligible SKU prices, existing resources and
   original October 28 storage coverage. No read acquisition or service change.
2. Set/read back existing-VM provider STOP at 4,500 seconds / no restart, then
   start only the existing VM. All setup, hashes, native gates, science,
   collection/upload/readback share 3,600 seconds from the provider start.
   Record actual guest mount, eight CPUs, RAM, free and initial used disk bytes.
3. Fetch via the existing read-only GitHub key into a new detached exact-source
   checkout. Preserve original checkouts and caches. Use the passed E017 lexical
   Python environment read-only; verify complete distribution/import/library/
   installed source identities. No recopy/reinstall fallback or new wheel.
4. Start a held parent with `scripts/e018_arm.py`; bind/test a fresh watcher to
   this boot/PID/start/command identity, including normal/crash detector tests,
   and retain live status before release. Provider STOP stays independent.
5. `scripts/e018_bootstrap.py` runs seven bounded native gates: retained bytes,
   complete existing runtime/source/libraries, full DNA/ordered ten-depth or
   sequence-only axes, new selection/refusal tests, actual retained tiny cached
   marker/refiner/export, launcher/collector contracts and serial DAG dry-run.
   No graph/index/profile/learning/marker search on either community.
6. Release only after config/source/budget/credits/storage/headroom/native gates
   and matching live watcher pass. `scripts/e018_control.py` executes serial
   cached selection -> unchanged E013 refinement -> full export -> independent
   cache/selection readback, then the second community. Four-core local executor,
   no `--jobs`, and explicit barrier; every substantial rule has a benchmark/log.
7. Verify unchanged retained bytes, bound member inventory and <= 2 GiB archive
   before upload, then read back archive/checksum/collection. Preserve original
   omitted DNA on disk. Publish compact guest status `e018-candidate/status`
   and private completion. Bound watcher collects its exit snapshot and stops
   compute. Independently verify TERMINATED; stop is not proof of success.

Operational repair can use fresh journals and byte/source/runtime-verified reuse
inside the same clock/budget. Never replay an accepted scientific stage, extend a
clock, change the scientific rule or discard failures. For a healthy longer job,
verify real progress/supervision, wait a few minutes and hand off; follow a short
job through collection/shutdown. On failure or limit collect evidence and stop.
