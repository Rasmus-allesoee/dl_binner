## Where recovery is being lost

- Source/runtime/axes and native unit vectors pass. All three calibration pair
  distances reproduce exactly on the retained source-blind cohorts (16,300 /
  16,360 pairs); missing cells are zero. Measured all-zero profiles stay distinct
  from missing data. Parent-depth dispersion is not measured window variance.
  Sampled technical retrieval recall passes the unchanged 0.90 gate in every
  populated stratum. This does not establish biological homogeneity.
- The reliable-core graph is extremely sparse: **6,810 of 9,812 E009 cores** and
  **41,414 of 60,211 Oral cores** are singleton components, containing 56.21 Mb /
  490.68 Mb. The forest has 7,136 / 44,951 components before marker selection.
  Selected core bins contain 76.00 Mb / 473.07 Mb of 133.05 Mb / 1,008.85 Mb core

  contigs; this was declared, not an accidental input cutoff.
- E009 final bins: 181 / 229 are below the primary 200 kb threshold. Oral:
  2,201 / 2,411. Much assigned DNA is in small fragments; the bin count itself
  is not recovery evidence. A blanket minimum-bin-size reduction would change
  the benchmark, not repair recovery.
- Of the unselected queries, **72,801 / 86,272 E009** and **459,291 / 493,998
  Oral** have no accepted core neighbors. Only 1,306 / 10,619 have agreeing
  neighbors but no selected core voter. Marker-cap rejections are zero / 66;
  another marker-cap tweak is unlikely to address the dominant loss mechanism.
- The all-informative-channel rank <= 0.20 agreement plus reciprocal top-10 rule
  is correctly implemented. Its raw agreement uses unshrunk ranks; there is no
  accidental short-length score floor in this path. Nevertheless, marginal ranks
  are not common-genome probabilities, and an AND gate can sever biological links.
  The native query path also uses about 1.10 sampled CPUs despite an eight-vCPU

## One strongest next block

**Build and locally contract-test one common CPU composition/context + genuine
parent-depth + reliable-marker-learning pipeline, with one supported biological
bin-construction path, on both communities.** This is a coherent full-version
upgrade and evaluation repair, not another rank/resolution grid. Use the existing
real DNA views and measured ten-depth tables; keep the documented all-DNA/short/
marker-negative and abstention behavior. Use depth in learning on both, rather
than only in Oral's grouping. Resolve the precise common objective and soft
support/selection defaults prospectively during implementation. Avoid E026's
universal marginal-rank veto and an unexplained contig-count ban on otherwise
supported long DNA; do not automatically assign isolated or ambiguous contigs.
Keep sequence context compact unless a concrete contract warrants a larger model.

The primary common mode should **exclude frozen GLM on both datasets, including
bootstrap teachers and pair proposals**. E022's E009 proposals currently depend
on the E021 GLM-enabled teacher; removing only the student's GLM input would leave
a hidden asymmetric prior. Construct the same label-free bootstrap/proposal path
for both. Its retained bootstrap output can provide one useful selective control
against the marker-informed student with the same grouping; do not require a
factorial campaign or extra fit for every ingredient. Freeze one source/default/
feature-availability policy and prospective full-population criteria before any
changed outcomes. This defines a common mode, not a decision to remove GLM from
the product or a transfer claim for the GLM-enabled mode.

Why now: Oral now has genuine reusable depth and its representation has never
learned from it; E009 shows that a GLM-enabled representation does not protect
against a brittle bin constructor. This block addresses both measured limitations
and finally removes the historic version confound. A matched comparison can show
whether the coherent system improves recovery; it will not isolate all causes.
Do not select different defaults or versions for the two communities after scores.

Serious alternatives:

- **Full Oral GLM parity** is scientifically useful and remains available. It
  needs Oral extraction, a common GLM-enabled bootstrap and student, not merely
  adding a bank to the E019 student. Existing workload: 508,763 parents,
  2,470,549 available views, 2.366 Gb exposed DNA, a lower bound of 2,707,640 4,000 bp chunks,
  994,274,203 projected tokens and a 7.815 GB fixed-slot bank. The retained
  61.05 GPU-hour projection is not a full-Oral measurement. E009's measured
  extraction was 4.14 GPU hours; its 8.24-hour GPU allocation included setup and
  handoff. DCVBin's >=2 kb, one-parent/truncated/one-orientation inputs are a
  different treatment, not a drop-in speed claim. A fresh native throughput/
  pooling/precision gate is required before using batching estimates. Do not
  alter cutoffs or substitute parent vectors silently. Common depth learning
  and supported bin construction currently address more direct evidence; price
  alone does not reject GLM. The retained [E021 comparison](../../experiments/E021-frozen-sequence-hybrid/comparison-review.json)
  gained 0.5116 R95 percentage points on E009 (ten target gains / 15 losses),
  while target-90 fell from seven to six; Oral was unrun. That positive but mixed
  bundle evidence does not establish a necessary full-Oral GLM prerequisite.
- Another frozen threshold control would preserve causal simplicity but leave
  both learner asymmetry and Oral's unused learning information unresolved.
  Bigger transformers or marker-aware losses alone do not repair absent graph
  support. A stronger external binner could reveal more headroom, but retained
  MetaBAT2 and the existing source evidence already justify this development
  step. No new external campaign is needed first.
- More data are needed for generalization, not to tune E026 away from its failed
  criterion. Keep skin unscored until the common version and prospective
  confirmation protocol are ready; neither development community is confirmation.
