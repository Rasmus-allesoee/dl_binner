## Comparison studies that shape the first experiment

| Source | What it contributes | Important boundary |
| --- | --- | --- |
| [Yazhini et al., 2025](https://doi.org/10.1093/bib/bbaf617), [local copy](../../agent_context/papers/benchmarks/Arangasamy_2025_paper.md), section on embedding and clustering accuracy | Explicitly compares representation quality, native clustering, and a shared COMEBin clustering procedure. The order of methods changes with the endpoint. | A shared clusterer is a diagnostic control, not inherently neutral: metric, normalization, density, and marker treatment can favor particular embeddings. A within-dataset linear probe does not establish generalization to unseen genomes. |
| [Kim et al., 2026](https://doi.org/10.1038/s41467-026-71521-w), [local copy](../../agent_context/papers/benchmarks/Kim_2026_paper.md), abstract and study design | Varies community complexity, sequencing depth, and sample count; includes chimerism and ensemble analysis. | Its preferred sample count and ensemble gains belong to the tested conditions. Several tested software versions predate the publication year. |
| [Han et al., 2025](https://doi.org/10.1038/s41467-025-57957-6), [local copy](../../agent_context/papers/benchmarks/Han_2025_paper.md), abstract and introduction | Compares sequencing platforms and binning modes; makes long-read/hybrid methods serious alternatives. | Real-data quality estimates do not provide exact contig origin. Cross-platform gains include changed assembly quality and cannot be attributed to a binner alone. |
| [Coleman et al., 2026 / MAG-E](https://doi.org/10.64898/2026.04.06.712906), [local preprint](../../agent_context/papers/evaluation/Coleman_2026_paper.md), abstract and initial results | Evaluates whole pipelines against simulated source genomes and reports quality-estimator and contig-level failures. | Ecosystem-matched simulation is useful, but the reference collection and definition of eligible/recoverable genomes influence the result. Publication status was not fully refreshed; the inspected local source is a preprint. |

These papers report different advantages for workflows, tools, and refinement. This is not enough to declare one paper wrong. Compare assembly provenance, mapping reference, clustering population, software version, truth definition, and evaluation population before interpreting their disagreement.

## Limited code inspection

All referenced local files are identified in [context-sources.sha256](context-sources.sha256). Their upstream commits are unknown; these observations must be rechecked on the versions chosen for execution.

- COMEBin's [training entry point](../../agent_context/tools_repo/COMEBin-master/COMEBin/train_CLmodel.py), `train_CLmodel`, reads feature/normalization options and recognizes an existing `embeddings.tsv`. Its [clustering entry point](../../agent_context/tools_repo/COMEBin-master/COMEBin/cluster.py), `cluster`, reads `args.emb_file`, contig IDs, lengths, and `args.seed_file`. This supports a possible stage-level experiment but is not proof that arbitrary swapped embeddings work without adaptation.
- SemiBin's [cluster module](../../agent_context/tools_repo/SemiBin-main/SemiBin/cluster.py), `run_embed_infomap`, builds neighbor graphs from both embeddings and input features, then intersects them. A test that treats clustering as a function of the embedding alone would omit part of the native method.
- The local [VAMB README](../../agent_context/tools_repo/vamb-master/README.md) includes TaxVAMB, original VAMB, and a deprecated AVAMB description; [taxvamb_encode.py](../../agent_context/tools_repo/vamb-master/vamb/taxvamb_encode.py) contains taxonomy/semisupervised data handling. This was a file/entry-point inspection, not a mathematical audit of its loss.
- DCVBin's [README](../../agent_context/tools_repo/dcvbin-main/README.md) mentions sample coverage and two-stage clustering. Its [myencode.py](../../agent_context/tools_repo/dcvbin-main/myvae/mainfiles/myencode.py) has depth, sequence-feature, and abundance inputs. The paper emphasizes replacing coverage. Dormant/inherited code or version differences are possible explanations; trace the executed shell/CLI path before deciding there is a discrepancy in the actual evaluated method.

## Audit to finish before method design

Use a small baseline set initially: MetaBAT2 as an inexpensive control, VAMB as a comparatively simple learned reference, and one or both of COMEBin/SemiBin2 as strong references. Add the closest contemporary competitor to the chosen hypothesis: TaxVAMB for taxonomy, CompleteBin/DCVBin for sequence representations, or LorBin/SCGBinner for long reads. Assess QuickBin for the cost/purity comparison. This is a shortlist, not a frozen benchmark suite.

For each selected method, establish: exact software/model/database version; required input information; preprocessing and normalization; training objective and supervision; clustering/refinement and internal quality score; supported native workflow; output assignment/embedding access; overlap with evaluation genomes; and resource requirements. Read UncertainGen and GenomeFace closely before proposing any novelty based on uncertainty or adaptive weighting.

Stop expanding the survey once it supports one concrete residual-failure question, its closest prior art, and a falsifiable experiment. Refresh the relevant sources again before a novelty claim or final benchmark.
